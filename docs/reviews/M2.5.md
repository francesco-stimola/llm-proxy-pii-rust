## M2.5-R1 — the "no new native deps" claim was false · leanness + docs accuracy · **closed 2026-07-12 (Option A)**

**Finding.** `Cargo.toml`'s comment, `DEVLOG.md` and the M2.5 dependency bullet all claimed hf-hub was
*"built on the `reqwest` already in the tree — no new native deps"*. Confirmed with
`cargo tree --features onnx` that this is **inaccurate**. Under `--features onnx`, `hf-hub 1.0.0` pulls:

- a **second `reqwest 0.13.4`** (the in-tree one is `0.12.28`)
- **`hf-xet 1.5.3`**
- `rustls 0.23` → **`aws-lc-rs` + `aws-lc-sys`** (native C/asm crypto)
- `reqwest-middleware 0.5`, `ureq 3`

**Why the obvious trim does not work.** Verified in `hf-hub 1.0.0`'s own `Cargo.toml`: `hf-xet` and
`reqwest 0.13` are **non-optional** — not behind any feature. Its *only* features are `blocking`,
`rustls-tls`, `socks`, and `default = []`. **No feature combination can drop them**, and
`default-features = false` is a no-op (the default is already empty).

**The only way to shed them is a downgrade.** `hf-hub 0.4.3` has `reqwest ^0.12` as an **optional** dep
(it would unify with the in-tree `reqwest 0.12.28`, native-tls/schannel) and has **no `hf-xet`, no
`aws-lc-rs`, no `rustls`, no second reqwest** — adding only small pure-Rust crates (`dirs`, `indicatif`,
`num_cpus`, `rand`). But its async API differs (`api::tokio::ApiBuilder` + `Repo::with_revision`), so
`src/pii/hf.rs` would need a rewrite.

### Decision (user, 2026-07-12) — **Option A: keep `hf-hub 1.0`**

The whole footprint is **`onnx`-gated**, and the `onnx` feature is *already* native (`ort` links the ONNX
Runtime C++ library) — so a maintained, audited crypto library is **no new category**. The **default build
stays native-dep-free**. Downgrading to the **unmaintained** 0.4.3 (no upstream CVE fixes) is the **worse
security posture for a privacy tool**. A hand-rolled fetch remains the fallback only if the supply-chain
surface ever becomes a concrete problem.

**Builder tasks — done.**
- Corrected the three inaccurate "no new native deps" claims (`Cargo.toml` comment, `DEVLOG.md`, the M2.5
  dependency bullet) to state the real onnx-only footprint.
- Added the **footprint guard** `tests/dependency_footprint.rs`
  (`default_build_excludes_the_onnx_and_hf_stack`, `DEP-01`): `cargo tree` on the **default** features must
  contain no `hf-hub` / `hf-xet` / `aws-lc` / `ort` / `tokenizers`. **Verified non-vacuous** — all five are
  present under `--features onnx`.

> The lasting rule: **the default build is native-dep-free, and that is now enforced by a test, not by a
> comment.**

## M2.5-R2 — an empty `id2label` returned `Ok(vec![])` · fail-closed hygiene · **closed 2026-07-12**

**Finding.** `parse_id2label` checked contiguity but accepted an **empty** `id2label` object, returning
`Ok(vec![])`. The failure then surfaced later, at request time, as a mysterious decode mismatch — instead
of at load, where it belongs.

**Fix.** `anyhow::ensure!(!pairs.is_empty(), …)` after the contiguity check → fails closed at load.

**Test.** `empty_id2label_is_an_error` (`HF-01`).
