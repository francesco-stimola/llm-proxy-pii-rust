## Review — M2.6 + M2.5-R2 (2026-07-12) — sound, no blockers

Verified independently: **66 tests green (default) / 74 + 1 `#[ignore]`d (`--features onnx`), no
warnings**; `cargo test --features onnx --no-run` compiles the whole tree clean.

**The debug modes do not weaken fail-closed — checked, not assumed.** Request-side masking (`on_request`)
runs **unconditionally** in `chat_completions`; `PII_DEBUG_SKIP_DEMASK` guards **only** the `on_response`
de-mask loop. So with the flag on, the upstream *still* never sees raw PII — the flag only changes what the
**local client** gets back (the placeholders, as proof the round-trip is wired). The flag is off by
default, emits a loud startup `warn!`, and the fail-closed block path returns **before** it is ever
consulted.

**The `trace!(masked_request)` log fires *after* masking and before forwarding** — placeholders only. The
de-masked client response is **never** logged. Verified by inspection *and* a codebase-wide log-site
sweep: every log site emits a kind, a placeholder token, or static text.

Two **non-blocking** hardening nits followed. Neither was a defect in the shipped behaviour — they close
the gap between *"we checked this by reading the code"* and *"the suite would catch it if someone broke
it"*.

### Nit 1 — the never-log-raw-PII rule was verified by *inspection*, not by a test · **closed**

**Finding.** The project's #1 risk (a log line carrying a real value) was guarded only by a code-review
sweep. A future refactor could silently turn a safe log into a leak, and nothing would fail.

**Fix.** `tests/log_safety.rs` — `crate_logs_carry_placeholders_never_raw_pii` (`DBG-02`). It captures
**this crate's** logs at `trace` level via a custom `MakeWriter` (`EnvFilter llm_proxy_pii_rust=trace`)
while driving a **real PII round-trip**, then asserts:

- the emitted `trace!(masked_request)` contains the **placeholder** (`[EMAIL_1]`), and
- it **never** contains the raw value, while
- the **reply really did** carry the de-masked value — so a genuine log leak would be caught, and the test
  can't pass vacuously by simply never producing PII.

It lives in its **own single-test file** on purpose: it must own the global `tracing` subscriber to
capture logs emitted from spawned tasks.

> **The never-log-raw-PII rule is now automated, not aspirational.** It is not a backlog item — it is an
> enforced quality bar, and this is the thing that enforces it.

<a id="m26-n2"></a>
### Nit 2 — three copies of the env-flag parser · cleanup · **closed**

**Finding.** `PII_DEBUG_SKIP_DEMASK`, `NER_REQUIRED` and `NER_TOKEN_TYPE_IDS` each parsed their own
truthy value. Three parsers, three chances to diverge — and one of them gates a **fail-closed** switch.

**Fix.** One `pub(crate) config::env_flag`, imported by `server.rs`. All three now share the single
`1` / `true` / `yes` / `on` parser.
