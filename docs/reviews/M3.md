## Review — SSE streaming + Option A routing (2026-07-12) — sound, no blockers

Verified independently: **73 tests green (default) / 81 + 1 `#[ignore]`d (`--features onnx`), no
warnings**; `cargo test --features onnx` compiles **and links** the `ort` native library clean (the
`binary_smoke` test boots the real linked binary).

**Fail-closed holds for streaming.** `chat_completions` runs the `on_request` mask stages **and** the
block check *before* the `stream:true` branch (`server.rs:245-267`), so a streaming request is masked
identically and a blocked one returns 400 without ever forwarding. The provider only ever sees
placeholders; streaming de-anonymization (`src/stream.rs`) is **client-side only** — the safe direction.

**The hold-back buffer is sound.** The held-back tail is length-bounded to 32 chars (our longest
placeholder body, `[ORGANIZATION_NN`, is ~15 — it never over-holds); it slices only on the ASCII `[`
boundary (no multi-byte panic); and **no content is dropped** — `demasking_sse_body` calls
`SseDemasker::flush()` exactly once at stream end, and `flush_pending` is idempotent via the `flushed`
guard (also fired pre-`[DONE]`), so the final held tail is always emitted.

**Secrets are redacted.** `Config`'s manual `Debug` shows `upstream_api_key` as `<redacted>` and
`upstream_extra_headers` as **names only** (their values may carry a Copilot integration id or token), so
the startup `info!(?config)` cannot leak one. `forward_request_headers` is an allowlist of header *names*,
not secrets.

**No preset can bypass masking.** The provider presets (`openai` / `copilot` / `anthropic`) set only the
OpenAI-compat *shape* — path, client-header allowlist, static headers. Masking is **schema**-based and
provider-independent. *(Pinned later, in M4, by `e2e_masking_is_provider_agnostic`: the same request via
the `openai` vs `anthropic` presets yields a **byte-identical** masked body upstream.)*

**Log sweep:** `src/stream.rs` emits **no** logs at all, and every streaming/routing log site carries only
static text, an error object, or the placeholder-only masked body.

## M3-R1 — a `stream:true` request answered with JSON was force-wrapped as SSE · robustness · **closed**

**Finding.** `stream_chat_completions` assumed the upstream response *is* an event stream. But an upstream
answers a `stream:true` request with a plain **JSON error** (401, 429, …) all the time — and a provider may
simply ignore `stream`. The proxy wrapped that JSON in an SSE frame, so the client got a malformed
event-stream instead of its error.

Not a leak — a robustness gap that would look like a proxy bug to every client hitting a rate limit.

**Fix.** `stream_chat_completions` branches on the upstream response's **`content-type`**. When it isn't
`text/event-stream`, it falls back to the buffered path (`buffered_fallback`): forward the **real** status
and content-type, and run the normal `on_response` de-mask.

**Test.** `e2e_streaming_non_sse_error_falls_back_to_json` (`STR-06`) — upstream returns
`429 application/json`, the client sees `429` + `application/json` + the error body.

## M3-R2 — a de-masked value with a `"` broke tool-call JSON · correctness (pre-existing) · **closed**

**Finding.** `Vault::demask` did **plain string substitution**. The `tool_calls[].function.arguments`
field is a **JSON-encoded string**, so restoring a real value that contains a `"`, a `\`, or a control
character produced **invalid inner JSON** — and the client could no longer parse the tool call.

Pre-existing (it predates streaming), not a leak, but it breaks the headline feature: the whole point of
the prompt augmentation is that the model can put placeholders **in tool-call arguments** and get real
values back.

**Fix.** `Vault::demask_json_string` — JSON-string-escapes the substituted value (via `json_string_body`
= `serde_json::to_string` minus the outer quotes). Wired into the **`arguments`** fields on **both** paths:

- buffered — `demask_response` (`src/pipeline/privacy.rs`)
- streaming — `SseDemasker::demask_for`, selected for `StreamKey::ToolArg`

`content` deliberately keeps the **plain** `demask` — it is not JSON-encoded, and escaping it would put
literal backslashes in the user's prose.

**Tests** (`STR-07`). `demask_json_string_keeps_inner_json_valid` (vault),
`tool_call_arguments_demask_stays_valid_json` + `content_demask_is_not_json_escaped` (buffered),
`tool_call_arguments_deanon_stays_valid_json` (streaming).

**Verified non-vacuous** in the M4 first-landing review: `demask_json_string_keeps_inner_json_valid`
asserts that the *plain* path **would** produce invalid JSON, so the test fails if the escaping is removed.

## Deferred from M3 — genuine non-leaks

Three follow-ups were deferred, and the review confirmed each is a **non-leak** before agreeing to defer:

- **Streaming de-anon of `delta.tool_calls[].function.arguments`** — landed in the M3 close-out
  (`6e69522`): `SseDemasker`'s hold-back buffers are now keyed by field
  (`StreamKey::{Content{choice}, ToolArg{choice,tool}}`), so a placeholder split across streamed tool-call
  argument deltas is reassembled too (`STR-04`).
- **Terminal SSE error events** — landed in the same commit: a mid-stream upstream error flushes buffered
  content, emits `event: error`, and ends cleanly instead of aborting the connection (`STR-05`).
- **Request-level provider routing** — **moved to Backlog** (user's call). Per-instance
  `UPSTREAM_PROVIDER` already covers Copilot + Anthropic (run one instance per provider); a clean
  per-request form is non-trivial. **Not a privacy change** — masking runs *before* routing, so a mis-route
  is a wrong-provider error, never a leak.
