### The maintainer's open item, closed

**The over-mask bar for the VAT tier** (ROADMAP → M11 Track A, *"A third decision"*, taken 2026-09-03):
zero bare-form `TaxId` spans over the real ~22 KiB Claude Code turn in `tests/common/m7_turn.rs`.
Built as `tests/vat_overmask.rs` — `VAT-15` and `VAT-16`, modelled on `tests/phone_overmask.rs` and
running over the **shared** fixture, not a copy.

| Quantity | Expected (written before the run) | Observed | Re-runs |
|---|---|---|---|
| `TaxId` spans over the turn | 0 | **0** | 3 |
| Masked spans of any kind that are exactly 11 ASCII digits | 0 | **0** | 3 |
| 11-digit tokens present in the turn (the denominator) | 0–3 | **0** | 3 |
| Fixture size | > 20 000 bytes | **22 823** | 3 |
| All-digit tokens in the turn / longest run | — | **11 / 5 digits** | 3 |

**The bar is met.** `0.100` (`VAT-09`) stands as a published *synthetic worst case*.

**The residue, stated because a passing test cannot state it.** The denominator is **zero** — the turn
contains no 11-digit token at all — so mod-10 was never invoked on this traffic. The zero therefore says
*this traffic offers the bare P.IVA nothing to bite*, which is weaker than PHONE-OM's zero, whose
candidate set is every plausible digit group. Traffic carrying 11-digit database ids or order numbers is
uncovered, and there `0.100` is the number that applies. Promoted to
[`TESTING.md`](../TESTING.md) → `VAT-15`, and the guard prints the denominator on every run so this cannot
quietly become a precision claim.

**Two assertions, not one.** `TaxId` ranks below `NationalId` and `Phone` (`VAT-14`), so an 11-digit run
the bare recognizer claims can be *named* by another tier and vanish from a `kind == TaxId` filter while
still being masked. The second assertion filters on the **shape** instead, and mutation M2 below is what
shows it earns its place.

### M11-R0 — `cargo fmt --check` was red on `main`, and CI gates on it — *high*

**Found while verifying, not by reading the diff.** `cargo fmt --check` fails on four files the M11
feature commits touched: `src/pii/onnx.rs` (6 hunks), `src/pii/recognizers.rs` (1), `src/pipeline/privacy.rs`
(1), `tests/m7_latency.rs` (1).

**Confirmed pre-existing rather than assumed**: `git show HEAD:<file>` into a scratch copy, then
`rustfmt --edition 2021 --check` on each — all four red on the `HEAD` blob, before any change of mine.

**Why it matters.** `.github/workflows/ci.yml:35` runs `cargo fmt --check` as a gate job. M11 as committed
would have failed CI on push. It survived because the milestone had had zero review rounds — this is
literally the first thing a round finds.

**Fix.** `cargo fmt` (commit `style:`). **Test.** The gate itself: `cargo fmt --check` exits 0, and
`cargo clippy --all-targets -- -D warnings` plus `cargo clippy-onnx -- -D warnings` are both clean.

**Closed 2026-09-03.**
