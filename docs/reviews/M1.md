# Review findings — M1 / M1.5 (structured PII pipeline · robustness & fail-closed)

The **ledger** lives in [`../ROADMAP.md`](../ROADMAP.md#m15); this file is the record.

Eight findings across the M1 and M1.5 reviews, **all closed** — commits `bb68707` and `775945f`
(2026-07-11). They pre-date the `M<n>-R<n>` numbering scheme, so they have no ids; they are listed here in
the order they were fixed. Blow-by-blow detail is in [`../DEVLOG.md`](../DEVLOG.md) (2026-07-11).

Notably, this is the round that established the two rules the rest of the project runs on: **fail closed**
(a privacy tool's failure mode *is* the product) and **never log raw PII**.

## Closed in `bb68707` — the M1 review

### IBAN over-match — the span absorbed a trailing ALL-CAPS word
The IBAN regex was open enough to swallow the capitalised word that followed the account number. Replaced
with **two canonical shapes**, no trailing ALL-CAPS. Guard: corpus `IBAN-04` — the IBAN span never absorbs
a trailing word. *(The same "open pattern swallows the neighbour" shape came back as the phone over-match
below, and was fixed the same way.)*

### `iban_mod97` was computed and thrown away
The checksum function existed but nothing consumed it. Wired via `confidence_of`, which introduced
`PiiEntity.confidence` / `Confidence` (`Verified` | `Structural`) and `PiiKind::from_label`.

**The decision it forced:** IBAN detection stays **structure-based** — a mod-97 failure does **not** reject
the match, it only downgrades the confidence — so *synthetic* IBANs are still masked. Privacy-first: a
structurally-valid IBAN we can't verify is still masked, never forwarded.

### Prompt augmentation appended a second `system` message
The augmentation injected its own `system` message even when the request already had one. Some providers
only honour the first. Now it **merges into the existing** `system` / `developer` message.
Guard: `SYS-01` / `INT-07` — exactly one system message reaches the upstream.

### Response headers were forwarded wholesale
The body is **re-serialized** after de-masking, so a forwarded `content-length` is stale and
hop-by-hop headers are meaningless. Replaced with a safe **allowlist** (`retry-after`, `x-request-id`,
`x-ratelimit-*`, `openai-*`, `anthropic-*`); `forward_chat_completions` now returns a `HeaderMap`.
Guard: `HDR-01`.

### De-masking was a double scan (CR-4) and intolerant of model-mangled placeholders
Models don't reproduce `[EMAIL_1]` byte-for-byte — they emit `[EMAIL 1]`, `[email-1]`, `[ EMAIL_1 ]`.
Replaced with a **single tolerant pass** that restores all of those; an unresolved but *known-kind*
placeholder is `warn!`ed rather than silently shipped. Guard: `DEM-01`.

## Closed in `775945f` — the M1.5 review (all three in the reviewer's own prior code)

### Array-content fail-closed gap — **a leak**
`mask_content` skipped array elements that weren't objects, so a **bare string** inside a `content` array
was forwarded **unmasked**. Now: bare-string elements are masked; object parts have their `text` masked
(non-text parts like `image_url` are skipped); any **other** scalar **fails closed**.

### Phone international over-match
The open `\+\d{1,3}(?: \d{2,7}){1,4}` swallowed the trailing number group. Replaced with two canonical
shapes (3-group, then 2-group) — the same fix as the IBAN over-match above.

### `Confidence` was write-only
It was computed and stored, and nothing ever read it — the audit signal existed on paper only. `detect`
now `debug!`-logs each `Structural` match. **Kind only, never the value** — this is the log site the
never-log-raw-PII rule was first written for, and it is guarded by `DBG-02` since M2.6.
