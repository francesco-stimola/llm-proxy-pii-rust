## Review 1 — the NER detector (2026-07-12) — 9 findings

Verified: `cargo build --features onnx` compiles clean, the default build stays native-dep-free.

The dominant theme: **the NER layer had no fail-closed story.** A model that failed to load, or threw
mid-inference, silently degraded to structured-only detection — for *names*, which is exactly what the
NER exists to catch. M2-R1 and M2-R2 fixed the mechanism; the rest are robustness in the ONNX plumbing.

<a id="m2-r1"></a>
<a id="m2-r2"></a>
### M2-R1 / M2-R2 — the NER could fail silently · **closed**

**Finding.** A detector error was swallowed. For a privacy tool, an undetected `Person` is a **leak** —
but making the NER *unconditionally* fail-closed would make a model download failure a hard outage, which
isn't always what an operator wants. So the fix had to make the posture **explicit and configurable**,
not pick one.

**Fix.**
- `PiiDetector::try_detect -> Result<_, DetectError>` (default impl = `Ok(detect())`), so an engine can
  report failure instead of returning an empty set.
- `CompositeDetector` **propagates** sub-detector errors; `PrivacyStage` sets `ctx.block` → **400** when a
  *required* detector errors.
- `FailOpen(Box<dyn PiiDetector>)` explicitly opts a non-critical detector **out** — fail-open is now a
  visible wrapper in the code, not an accident.
- **`NER_REQUIRED`** env switch: `build_detector(required) -> Result` and `AppState::new -> Result`, so a
  required-but-unloadable NER is **fatal at startup**, not at the first request.

**Default posture:** structured PII is *always* fail-closed; the NER is fail-**open** unless
`NER_REQUIRED` is set. Documented in ARCHITECTURE.

**Tests.** `FC-04`, `FC-05`, `CMP-02`.

<a id="m2-r3"></a>
### M2-R3 — a label/logit count mismatch was undetected · **closed**
`ner_decode::validate_label_count` — if `NER_LABELS` doesn't match the model's output width, every decode
is silently misaligned (a `PER` read as an `O`). Now it fails closed at load. Test `DEC-06`.

<a id="m2-r4"></a>
### M2-R4 — `outputs["logits"]` panicked; BERT-family models need `token_type_ids` · **closed**
Indexing the ONNX output map panicked on a model that names its output differently. Now
`outputs.get("logits")` returns a graceful `Err`. Separately, BERT-family models require a
`token_type_ids` input — added behind the `NER_TOKEN_TYPE_IDS` flag.

<a id="m2-r5"></a>
### M2-R5 — `B_LOC`-style labels didn't split adjacent entities · **closed**
`is_begin` only recognised the `B-` prefix, so a model emitting `B_LOC` / `I_LOC` (underscore) merged
*New York* and *London* into one span. Now both separators are handled. Test `DEC-05`.

<a id="m2-r6"></a>
### M2-R6 — an off-boundary token offset was silently dropped · **closed**
A token offset that didn't land on a `char` boundary was discarded without a word — a silent recall loss.
Now it `warn!`s (kind only).

**Closed by the live model run**, which answered the underlying question: the HF tokenizer emits **byte**
offsets, and non-ASCII text (`Müller`, a 2-byte `ü`) extracts on exact byte boundaries. The related
discovery — SentencePiece includes the **leading space** in a token offset (`▁Mario` = `" Mario"`), so
`decode_entities` must **trim whitespace** — took Person recall from **0.00 to above**, and is pinned by
`DEC-07`.

<a id="m2-r7"></a>
### M2-R7 — the whole-span drop for NER was undocumented · **closed**
`resolve_overlaps` discards an **entire** NER span that overlaps a kept structured span, rather than
keeping its remainder. Documented and tested rather than changed: abandoning an *unstructured* remainder
costs **recall, never a leak** — the opposite of the structured case.

> This distinction became load-bearing in M4: the structured partition got the
> [no-abandoned-bytes invariant](M4.md#the-fix-union-merge), while **NER kept this drop**. Test `OVL-02`.

<a id="m2-r8"></a>
### M2-R8 — `DetectError` could carry input text · **closed**
An error type that can hold the input is a log leak waiting to happen. `DetectError` now carries a
**static label only** — never any input text.

<a id="m2-r9"></a>
### M2-R9 — a poisoned mutex killed the session pool · **closed**
One panicking inference poisoned the `Mutex` guarding an `ort` session and every subsequent request on
that session failed. Now recovered via `into_inner`. *(The pool exists because `ort`'s `run` takes
`&mut self` — a round-robin pool of sessions, `NER_POOL_SIZE`, is what keeps inference off a single
thread.)*

<a id="m2-r10"></a>
### M2-R10 — the eval harness counted membership, not multiset · harness precision · **closed**
**Finding.** TP/FP/FN used `Vec::contains`, so two *expected* duplicate entities could both be satisfied
by **one** detection (inflating recall), and a spurious duplicate detection wasn't an FP.

**Fix.** `tests/ner_eval.rs` scores through a `tally` helper: each `(kind, text)` is counted as a
**multiset**, `tp = min(expected, detected)`.

**The recorded numbers were unaffected** (no corpus case has a duplicate `(kind, text)` in one sentence) —
as predicted before the fix, and confirmed after. Test `EVAL-02`
(`tally_counts_duplicates_as_multiset`, non-network) pins recall at 0.5, not 1.0, for a
two-expected / one-detected case.
